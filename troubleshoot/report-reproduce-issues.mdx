A useful report lets another person reproduce the problem and compare the result with your expectations.

## Prepare a reproduction

1. Record the output of `SELECT version();`, your deployment method, and the upstream/downstream connector versions.
2. Reduce the schema and SQL to the smallest case that still fails. Include the relevant `CREATE TABLE`, `CREATE SOURCE`, `CREATE MATERIALIZED VIEW`, or `CREATE SINK` statements.
3. Provide a small synthetic dataset and the exact commands, in order, needed to reproduce from a clean state.
4. State the expected result and the actual result. Include the complete error text, timestamps with a timezone, and whether the failure is repeatable.
5. Include relevant node logs, resource settings, or metrics when the problem depends on load or deployment configuration.

Remove credentials, tokens, personal data and confidential records from SQL, connection strings, logs and screenshots before sharing them. Preserve the structure needed to reproduce the issue and replace sensitive values with placeholders.

## Report template

```text
RisingWave version:
Deployment method and cluster resources:
Connector and upstream/downstream versions:

Minimal schema and SQL:
Synthetic input data:
Steps to reproduce:

Expected result:
Actual result and error:
Timestamp/timezone and relevant redacted logs:
Recent upgrades or configuration changes:
```

## Choose a reporting channel

- Search [existing GitHub issues](https://github.com/risingwavelabs/risingwave/issues) before opening a new one. Use the [issue templates](https://github.com/risingwavelabs/risingwave/issues/new/choose) to report a reproducible product bug.
- For questions and help reducing a reproduction, ask in the [Community Slack](https://www.risingwave.com/slack).
- For a RisingWave Cloud project, contact [Cloud support](mailto:cloud-support@risingwave-labs.com) and include the project identifier through the support channel.

See [Troubleshooting](/troubleshoot/overview), [Performance troubleshooting](/performance/performance-troubleshoot-ov), and [System catalogs](/sql/system-catalogs/overview) for diagnostic tools.
